
# Contributing to Pixon

Thank you for your interest in contributing to **Pixon**! We welcome contributions of any kind — bug fixes, new features, documentation improvements, or helping with packaging.

---

## How to Contribute

1. **Open an Issue or Discussion**  
   If you find a bug, want a new feature, or have an idea, please create an issue or join the discussion.

2. **Fork the Repository**  
   Click the "Fork" button on GitHub to create your own copy of Pixon.

3. **Create a Feature Branch**  
   ```bash
   git checkout -b feature/my-feature
````

4. **Make Changes**
   Implement your feature, fix, or documentation improvement in your branch.

5. **Commit Your Changes**

   ```bash
   git commit -am "Add feature: description"
   ```

6. **Push Your Branch**

   ```bash
   git push origin feature/my-feature
   ```

7. **Submit a Pull Request (PR)**
   Go to the GitHub repository and create a PR from your branch. PRs are reviewed promptly.

---

## Coding Guidelines

* Follow **C++17** standards for the core library.
* Keep functions modular and reusable.
* For CLI commands, maintain consistent parameter ordering.
* Include comments and documentation for clarity.
* If adding a new feature, include usage examples in `README.md` or the `docs/` folder.

## Notes

* Testing your changes locally is strongly recommended before creating a PR.
* If your PR adds new dependencies, update the `dependency.sh` or documentation accordingly.
* Pixon follows a **single-source maintenance model**, so all official contributions should go through PRs for review.
